Start with the [Marble design system](../design-system/README.md).

Build a consistent type hierarchy, spacing, and alignment around the work people
do most often. Use a few strong visual accents. Keep frequent choices next to the
work they affect and put setup-only options in settings. Use familiar interaction
patterns in the product's own visual language.

Review the running app with representative data. Check first launch, a populated
main view, and switching between related views. Look for truncated names, overlapping
labels, awkward empty states, and lost reading positions or drafts. Fix problems
found in the actual flow, then recheck the affected screen. Use screenshots from
the running app as evidence when visuals are part of the deliverable.
