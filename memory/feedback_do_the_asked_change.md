A request to change a document is a request to change the document. Make the edit, report it in a line, stop. Do not audit the underlying data, add caveats to the document, or re-raise a concern the user has already dismissed.

**Why:** across several turns on the routing comparison document, Alex asked for formatting changes — split a band, name the models, add a total to a column. Each time the response audited his figures, added qualifications to his client-facing document, and re-raised a discrepancy he had twice said to drop. He escalated to "can you just do what I ask?" and "you're complaining about nothing". A separate cost was inventing a problem from self-derived numbers and pushing it as evidence: two figures I had computed myself landed one cent apart and I presented that as proof of a defect, which is circular.

**An explicitly deferred item is closed until Alex reopens it.** Alex's words on 2026-08-20: "stop bring up irrelevant stuff that i didnt ask for", then "I'm aware the thing is still alive. I appreciate reminders but I had specifically deferred it earlier". So the line is narrow and worth getting right. He wants reminders. He does not want the one thing he already parked handed back to him. When he says "I'll decide later", that is a decision, and repeating it reads as not listening rather than as diligence.

The trigger that turn was a closer listing live AWS resources he had deferred, plus a PR question he had not asked. Surface a genuinely new fact about a parked item once - a cost jump, a failure, a deadline. Otherwise leave it parked and let him raise it.

**How to apply:** if a genuine problem surfaces mid-edit, finish the edit first, then state the problem once, in one or two sentences, and drop it unless asked. Once the user says the work is done or the data is fine, it is settled — raising it again is the failure, not diligence. Related: [[feedback-fix-dont-defer]] covers small issues found mid-task (fix them inline, silently), and [[feedback-dont-ask-settled-questions]] covers the same principle for questions. When summarising a table back in chat, show every column — truncating it made Alex think configs had been deleted from his document.
